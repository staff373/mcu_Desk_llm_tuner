## Codebase Patterns
- Active Ralph execution files live under `scripts/ralph/`: `prd.json`, `progress.txt`, `CODEX.md`, and `archive/`.
- Each Story must update `project_status.md`, create a checkpoint under `.project_checkpoints/`, commit, and push.
- Current phase is no-hardware: do not open COM8 or any real serial port during default verification.
- Real serial commands must come only from YAML or validated `TuningSession` control flow.
- Early session-core tests can use root-level `unittest` files and patch `tuning_session.serial.Serial` with fakes to prove no real serial port is opened.
- Session control APIs should return `ActionResult`; rejected controls emit `action_rejected` events with `action`, `code`, `error_code`, `state`, and `session_id`.
- Pause/resume no-hardware tests can call `resume()` from the structured `paused` state event handler to avoid background thread timing sleeps while still exercising safe checkpoints.
- Safe-stop command outcomes are stored on `TuningSession.stop_command_results` and included in `summary()["stop_command_results"]` with statuses such as `succeeded`, `timed_out`, and `unavailable`.
- Stop-reason updates inside `TuningSession` should use `_apply_stop_reason(...)` so emergency `operator_abort` is not overwritten by generic manual-stop checkpoints.
- Manual rollback controls require `baseline_parameters` and an active session serial handle; keep the missing-baseline guard before active-connection checks so invalid controls stay no-hardware.
- Active parameter selection is session-scoped through `TuningSession.active_parameter_keys`; do not mutate `plan["step_policy"]["parameter_order"]` or source YAML-derived structures.
- Runtime execution should read `max_rounds`, `trial_window_ms`, and `cooldown_ms` through `_effective_runtime_limits()` so session-scoped overrides do not mutate YAML-derived `plan`.
- Standardized session failures should emit `error` events with `category`, `code`, `error_code`, `recoverable`, `state`, `action`, and `session_id`; these events are also JSONL records.
- Real serial access in `TuningSession` now goes through `PySerialTransport.from_config`; constructing the transport is side-effect free, and no-hardware tests can inject `transport_factory` instead of patching GUI or CLI layers.
- Virtual no-hardware flows should inject `VirtualTransport` through `TuningSession.transport_factory`; it is opt-in and never selected by port name or CLI defaults.
- Virtual scoring targets can be declared per test-only fixture parameter with `virtual_target`; `VirtualTransport` falls back to `current` when no target is declared.
- Agent-facing no-hardware controls live in `agent_console_probe.py`; inject `VirtualTransport` through `AgentControlFacade(transport_factory_provider=...)` and patch `tuning_session.serial.Serial` to assert no real serial port opens.
- The standalone agent probe CLI is `python agent_console_probe.py`; it uses `run_probe(...)`, blocks `serial.Serial`, validates required action/event coverage, and supports `--require-event` for missing-event negative tests.
- Session report export schema is enforced by `validate_session_report_schema(...)` in `agent_console_probe.py`; reuse it for later report, replay, and verification work.
- GUI automatic tuning defaults to a direct `SessionWorker` in `tuning_panel.py`; structured session events arrive on the Tk queue as `SESSION_EVENT` tuples, while `--run-backend subprocess` preserves the legacy runner path.
- GUI structured session events should route through `TuningPanel._update_from_session_event(...)`; keep subprocess/plain text compatibility on `_handle_line(...)`.
- GUI operator controls are keyed in `TuningPanel.operator_buttons` and should refresh through `_refresh_operator_controls()`; fake-session tests can assign `session` and `session_worker` directly without opening serial.
- GUI connection controls are keyed in `TuningPanel.connection_buttons` and refresh through `_refresh_connection_controls()`; port detection must stay enumeration-only and must not open or command a serial port.
